# MediaDash v0.9 — Design

**Date:** 2026-07-27
**Author:** crackruckles (brainstormed with Claude / ponytail mode)
**Status:** Draft — pending user review before implementation plan

## 1. Goal

Two things at once:

1. **Defensive hardening for Jellyfin 12.** Cross-ABI compatibility already shipped in v0.7.3 (one binary for 10.11 + 12.0 via reflection bridge over the `User` entity and `IUserManager.Users` → `GetUsers()` rename). v0.9 extends that with an explicit API audit and a repeatable manual verification against both host lines, so users upgrading their Jellyfin server don't hit surprises.
2. **Whole-library coverage.** MediaDash's scanners today are video-first. v0.9 folds in **music, audiobooks, books, comics, and artwork** so the same "detect and fix" experience covers every library kind Jellyfin natively supports.

Context: the author is winding down active development after v1.0 but is willing to accept 1–2 update rounds per year to keep dependencies fresh. This affects choices about new dependencies (accept SharpCompress) and infrastructure (skip docker CI, keep verification manual).

## 2. Non-goals

- **Audio re-encoder** — Quality scanner reports oversized audio, no fixer ships. Rationale: lossy transcoding of audio is a religious topic (lossless collectors) and a support-ticket generator to maintain after step-away.
- **Format converters** (EPUB↔MOBI, CBR→CBZ, M4B→MP3, FLAC→Opus, etc.) — outside the "surface what Jellyfin already knows" scope from PLAN.md.
- **Books/comics Quality scanner** — "oversized book" isn't a meaningful concept in the way an "oversized 4K encode" is.
- **Docker-based CI matrix** — high-maintenance infrastructure; manual checklist instead.
- **New library-acquisition or metadata-authoring surfaces** — same PLAN.md non-goals as always.

## 3. Coverage matrix

Every media kind Jellyfin natively supports gets appropriate scanner coverage. Empty cells are intentional non-goals.

| Type | Duplicate | Playability | Stale | MediaSorter | Quality |
|------|-----------|-------------|-------|-------------|---------|
| Video (Movie / Episode) | ✓ existing | ✓ existing (ffprobe) | ✓ existing | ✓ existing | ✓ existing |
| Music (Audio) | ✓ new grouping | ✓ ffprobe | ✓ verify + widen | ✓ verify + widen | ✓ detect-only |
| Audiobook | ✓ same as music | ✓ ffprobe | ✓ | ✓ | opt-in (default off) |
| Books (EPUB / PDF / MOBI / AZW3) | ✓ ISBN / Author+Title | ✓ new `BookProbeService` | ✓ | ✓ | — |
| Comics (CBZ / CBR / CB7) | ✓ file hash | ✓ new `ComicProbeService` | ✓ | ✓ | — |
| Artwork | — | ✓ new `ArtworkScanner` | — | — | — |

Fixers:
- **Duplicate**: existing fixer works unchanged — moves the losing copy to recycle bin regardless of media kind.
- **Playability**: existing fixer works unchanged — removes file after re-verification.
- **Stale**: detect-only for all kinds (already the video convention).
- **MediaSorter**: existing fixer works unchanged — `File.Move` into the configured target library folder.
- **Artwork**: new `ArtworkFixer` — deletes the corrupt file, triggers `ILibraryManager.QueueLibraryScan(itemId, ImageRefreshMode.FullRefresh)` so Jellyfin's own metadata pipeline re-fetches.

## 4. v12 hardening

### 4.1 Static API audit
Enumerate every `using Jellyfin.*` and `using MediaBrowser.*` in the source. Cross-reference each referenced type / method against the 10.11 → 12.0 changelog. For each identified break, wrap the call in a reflection bridge in the same style as the existing `UserApiBridge` in `Scanners/StaleContentScanner.cs`. Bridge helpers live alongside the scanner they support unless they're used from more than one place, in which case they move to `Compat/`.

### 4.2 Smoke test
Build v0.9-preview → deploy to localhost:8099 (v12 test server) → run every scheduled task in dry-run against the test library → tail Jellyfin logs for any `MissingMethodException`, `TypeLoadException`, or `FileNotFoundException`. Iterate until clean.

### 4.3 v10.11 regression
Prod (192.168.1.117, v10.11) is off limits for testing. Regression coverage uses a locally-run second Jellyfin instance from the official 10.11 docker image (or a second native install). Same dry-run sweep as 4.2. Runs once at release cut; not automated.

### 4.4 Deliverable
`tools/verify-cross-abi.md` — a manual checklist so any future contributor can rerun the audit + smoke test process. No CI matrix, no docker automation — that infrastructure would rot without the author's active involvement.

### 4.5 Acceptance
Every scanner completes a scan cycle on both host lines with no unhandled exceptions in Jellyfin logs.

## 5. Music library reach

### 5.1 Scanner behaviour
- **DuplicateScanner** — group audio items by MusicBrainz track ID via `ProviderIds`, fall back to `Artist + Album + Title + Duration±2s`. Keeper policy: same shape as video (higher bitrate wins, file size as tiebreak).
- **PlayabilityScanner** — ffprobe already handles `.flac`, `.mp3`, `.m4a`, `.opus`, `.ogg`, `.wav`. One adjustment: thorough-mode start+middle+end sampling collapses on short tracks — if `duration < 60s`, sample the whole file.
- **QualityScanner** — detect-only. Default ceilings: MP3 > 320kbps, AAC > 256kbps. Lossless codecs (FLAC / ALAC / WAV) skipped by default. Contributes to "Space you could reclaim" total. No fixer.
- **StaleContentScanner** — verify current implementation has no `BaseItemKind` gate; if it does, widen it. `UserItemData.LastPlayedDate` covers music playback natively.
- **MediaSorterScanner** — widen the kind ↔ collection-type mapping (see §8).

### 5.2 Config
No new UI. Existing "Enabled libraries" checklist already lists music libraries — scanners just stop skipping them.

## 6. Audiobook library reach

Audiobooks are stored as audio files in Jellyfin (`BaseItemKind.AudioBook`) and share the ffprobe path with music. All music-library changes apply to audiobooks automatically **except**:

- **QualityScanner** — off by default for audiobooks (spoken word is already low-bitrate; a 320kbps ceiling produces false positives). Single opt-in setting: `Quality scanner: also scan audiobooks`.

## 7. Book library reach

### 7.1 New probe service
`Probing/BookProbeService.cs`. Dispatches on file extension:

| Format | Integrity check | Dependency |
|--------|-----------------|------------|
| `.epub` | `System.IO.Compression.ZipFile.Open` succeeds; entry `mimetype` present and reads `application/epub+zip` | stdlib |
| `.pdf` | file starts with `%PDF-`; last 1KB contains `%%EOF`; `startxref` locatable | stdlib (raw `FileStream`) |
| `.mobi` / `.azw` | 78-byte PDB header; magic bytes at offset 60 read `BOOKMOBI` (MOBI) or `TPZ ` (Topaz) | stdlib |
| `.azw3` | PalmDoc container with MOBI header; magic bytes readable | stdlib |

Result shape: `{ ok: bool, reason: string? }`. Cached in a new `format_probe_cache` table keyed on `(path, size, mtimeUtc)`, same shape as existing ffprobe cache.

### 7.2 Duplicate detection
Group by ISBN via `ProviderIds` when present. Fallback: `Author + Title` normalized (lowercase, punctuation stripped). Keeper policy: prefer file with more provider IDs, tiebreak on file size.

### 7.3 DRM
Integrity checks verify container structure only. DRM'd EPUB (Adobe) or MOBI (Amazon) pass — we do not decrypt or convert anything. Stays inside the safety commitment.

### 7.4 Corner cases
- KEPUB (Kobo EPUB variant with extra XML) — passes normal EPUB check.
- Kindle `.sdr` sidecar folders — ignored (not a file).
- KFX (newer Amazon format) — not covered; user complaints route to a future release.

## 8. Comic library reach

### 8.1 New probe service
`Probing/ComicProbeService.cs`.

| Format | Integrity check | Dependency |
|--------|-----------------|------------|
| `.cbz` | `System.IO.Compression.ZipFile.Open` succeeds; at least one image entry | stdlib |
| `.cbr` | SharpCompress `RarArchive.Open` succeeds; at least one image entry | SharpCompress |
| `.cb7` | SharpCompress `SevenZipArchive.Open` succeeds; at least one image entry | SharpCompress |

Same result shape and cache table as `BookProbeService`.

### 8.2 Duplicate detection
Comics are stored under the same `Book` entity type as ebooks in Jellyfin — there is no distinct `Comic` `BaseItemKind`. For v0.9, comics therefore reuse the `Book` grouping path (ISBN → normalized name fallback). Keeper policy is the same as books: bigger file wins, since higher-resolution scans are usually larger. SHA-256 file-hash grouping is *not* implemented in v0.9 — add it only when a distinct `Comic` entity type appears in a future Jellyfin release, or when a user reports comic dupe-detection failing.

*Amended 2026-07-27 during implementation, once Jellyfin's SDK confirmed no distinct Comic entity.*

### 8.3 MediaSorter mapping caveat
Jellyfin stores comics under a Books-typed library — there is no separate `Comics` `CollectionType`. Comics will therefore not be flagged as "misplaced" when they live in a Books library alongside actual books. `// ponytail: verify at implementation; if a separate collection type appears in a future Jellyfin release, extend the mapping`.

## 9. Corrupt artwork scanner

### 9.1 Scanner
`Scanners/ArtworkScanner.cs`. For every `BaseItem` with attached images, walk `item.ImageInfos`:

- Skip remote URLs (only local artwork is our concern).
- Check zero-byte files.
- Decode with SkiaSharp (`SKBitmap.Decode`) — returns null for corrupt / truncated images. SkiaSharp is already a Jellyfin transitive dependency; no new package.
- Compare `ImageInfo.Length` with actual on-disk size (mismatch = flagged).

Emits `IssueType.CorruptArtwork`.

### 9.2 Fixer
`Fixers/ArtworkFixer.cs`. Deletes the corrupt file → calls `ILibraryManager.QueueLibraryScan(itemId, ImageRefreshMode.FullRefresh)`. Jellyfin's own metadata pipeline re-fetches from the configured provider.

### 9.3 Safety
Only touches Jellyfin-managed artwork (files inside Jellyfin's metadata folder). User-placed `poster.jpg` / `backdrop.jpg` alongside the media file is never touched — this is a hard safety invariant enforced by path checks.

## 10. Extensions to existing scanners

### 10.1 DuplicateScanner
Add per-kind grouping paths (music, audiobook, book, comic — see §5, §7, §8). Existing video grouping unchanged.

### 10.2 PlayabilityScanner
Dispatch on `BaseItemKind`:
- Video / Audio / AudioBook → existing `FfprobeService`.
- Book → new `BookProbeService`.
- Comic → new `ComicProbeService`.

Single `IssueType.Unplayable` for all kinds; single fixer handles all.

### 10.3 QualityScanner
Music: detect-only, default ceilings per §5.1. Audiobook: opt-in per §6. Book / Comic: not scanned.

### 10.4 StaleContentScanner
Verify no `BaseItemKind` gate is filtering out non-video items. If one exists, widen it. Otherwise no code change.

### 10.5 MediaSorterScanner
Widen the kind ↔ collection-type mapping:

| Item kind | Belongs in `CollectionType` |
|-----------|-----------------------------|
| Movie | `Movies` (existing) |
| Episode / Season / Series | `TvShows` (existing) |
| Audio | `Music` |
| AudioBook | `AudioBooks` (verify — Jellyfin may consolidate under `Books`) |
| Book | `Books` |
| Comic | shares `Books` — no misplacement detection possible until Jellyfin adds a separate collection type |

## 12. New dependencies

- **SharpCompress** (NuGet, MIT license). Handles RAR + 7z, which .NET's stdlib does not cover. Actively maintained. This is the one dependency accepted with full awareness of the maintenance cost.

Everything else uses stdlib (`System.IO.Compression` for ZIP, raw `FileStream` reads for PDF/MOBI headers) or existing transitive deps (SkiaSharp for image decode).

## 13. Config additions

Single new setting:

- **Quality scanner: also scan audiobooks** (checkbox, default off, lives in Settings → Quality).

All other new capability routes off the existing "Enabled libraries" checklist. No wizard changes, no new tabs. Existing users' configs upgrade with no user-visible changes.

## 14. Database migration

New `format_probe_cache` table (idempotent `CREATE TABLE IF NOT EXISTS`) with the same shape as the existing ffprobe cache:

```sql
CREATE TABLE IF NOT EXISTS format_probe_cache (
    path       TEXT PRIMARY KEY,
    size       INTEGER NOT NULL,
    mtime_utc  TEXT NOT NULL,
    ok         INTEGER NOT NULL,
    reason     TEXT,
    probed_at  TEXT NOT NULL
);
```

No schema change to existing tables. New `IssueType.CorruptArtwork` value added to the `IssueType` enum — SQLite persists as INTEGER, so old databases upgrade cleanly.

## 15. Tests

- `BookProbeServiceTests` — 8 fixtures (good/bad × EPUB, PDF, MOBI, AZW3).
- `ComicProbeServiceTests` — 6 fixtures (good/bad × CBZ, CBR, CB7).
- `ArtworkScannerTests` — 3 fixtures (zero-byte JPEG, truncated PNG, valid PNG control).
- ffprobe cache tests extended to FLAC + Opus + M4B (audiobook container).
- `tools/make-fixtures.sh` gains generators for all new formats (checked-in binary fixtures avoided where possible — generated at test time).

## 16. UI impact

None deliberate. Overview's "Broken files" and "Space you could reclaim" cards will start including counts from music / audiobook / book / comic / artwork issues automatically. If per-kind breakdowns become useful, that's a v1.0 concern — no new UI in v0.9.

## 17. Release plan

Follows the existing process: `tools/release.ps1 -Version 0.9.0 -Changelog "..."`. `manifest.json` `targetAbi` unchanged (still 10.11 minimum; 12.0 still advertised as the second target).

## 18. Skipped, add-when

- Docker CI matrix — add when someone volunteers to own it post-1.0.
- Audio re-encoder — add when a maintainer with strong opinions on lossy audio takes over.
- Format converters — add when a specific format becomes de facto and users complain in bulk.
- KFX (Amazon) support — add when Amazon documents it or an open reader implementation exists.
- Comic misplacement detection — add when Jellyfin ships a distinct comics `CollectionType`.

## 19. Verification checklist (release gate)

Before cutting v0.9.0:

1. Static API audit committed to `tools/verify-cross-abi.md`.
2. Localhost v12 smoke test: every scanner runs against test library in dry-run with zero unhandled exceptions.
3. Local v10.11 docker smoke test: same, zero unhandled exceptions.
4. Unit tests pass (`dotnet test`).
5. Manual fixture library scan: expected issue counts match (documented in test fixtures).
6. First-run wizard on a fresh Jellyfin install completes cleanly.
7. `manifest.json` MD5 matches the uploaded zip (release.ps1 handles this).
