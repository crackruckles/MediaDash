### FFmpeg and FFprobe overlap follow-up

A real FFprobe call completed while a paced MediaDash FFmpeg job was still running. One shared slot now covers direct MediaDash FFmpeg and FFprobe launches across probes, repair and decode jobs, and format converters. A waiting job can be cancelled. Time spent waiting does not consume its process runtime budget. The slot stays reserved until the running child exits, including when the operating system takes longer to stop it. Jellyfin's own transcodes and native library tools use separate execution paths. [Reproduction](../../artifacts/remaining-issue-repairs-worktree/artifacts/media-process-overlap-red.log) and [candidate identity](../../artifacts/remaining-issue-repairs-worktree/artifacts/media-process-queue-verified-evidence-identity.json).

Both local Jellyfin versions completed the owned detect, approve, fix, playback, rescan, and recycle restore workflow with the queue build. Both profiles were restored and stopped.
