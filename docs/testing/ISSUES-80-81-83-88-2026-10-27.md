## Implemented

- **#80:** indexed, deterministic latest-attempt lookup, request cancellation and chunking. Regression benchmarks use valid integer timestamps: one million history rows / 2,000 issues took 22.0 ms at the store layer. Live HTTP and browser checks below verify newest attempts under that load.
- **#81/#83:** retained `DetectOnly` is XML-serializable again; actual legacy files load, normalize to ManualApprove and persist through restart without losing unrelated settings or queued IDs/paths. Approval/listing/single/bulk paths explain disabled scope, protection and unavailable fix handlers. Artwork scope is tied to its owning item.
- **#81 progress:** fast ticks read the lightweight progress endpoint; heavy dashboard reads follow the 15-second cadence even during scans. The progress bar now uses numeric progress within a scanner instead of displaying only completed-stage ratios. Real-host testing exposed the stalled bar and prompted a red/green JavaScript regression.
- **#88:** native loading/reflection/decoder inspection faults, I/O failures and locked files are unverifiable, not corruption verdicts. Destructive action requires a current owner/image binding, enabled owner library, allowed managed root/link ancestry, unprotected source and freshly confirmed corruption. Content hashes span persistence and physical identity is rechecked immediately before recycling. Failures preserve source bytes, queue state and image bindings; rollback respects concurrent provider changes and same-type siblings. Existing recycle/history restore retains the owner binding across force swaps.
- Selected-library artwork rescans replace earlier detected findings rather than duplicating managed-metadata rows. A regression runs the actual ScanTask twice.

Artwork queue authorization is a dependency of #88. Orphan metadata authorization from #86 remains outside this change.
