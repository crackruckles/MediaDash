## New findings

### Critical (blocks launch)

- [x] **UV-C1. `Ungrouped` issue type completely invisible in UI.**
  Backend has `MediaGrouperScanner` + `MediaGrouperFixer` registered and producing `IssueType.Ungrouped`. UI has:
  - No `STR.types.Ungrouped` entry (falls back to raw key `"Ungrouped"` on Issues/History rows)
  - No `FIX_TYPES` array registration → no Settings card → user can't turn it off or change mode
  - No `UngroupedFixMode` property in `PluginConfiguration` → `GetFixMode()` falls through to `DetectOnly`
  **Trigger:** any user who sets Movies/TV target paths in the Media Sorter section. Their Issues tab shows literal `"Ungrouped"` text, no Approve button label, no ability to configure. Feature runs silently.
  **Fix:** add `STR.types.Ungrouped` (en.json entry exists), add to `FIX_TYPES` with mode key, add `UngroupedFixMode` property, add Settings card.

### High

- [x] **UV-H1. `WIZ_STEP_LABELS` has 17 entries; en.json `wizSteps` has 16.**
  My prior partial-merge fix (v1) works for length mismatches — but the missing 17th entry (Trickplay thumbnails, inserted since prior audit) is untranslated for all 8 non-English locales. English users are fine.
  **Fix:** add 17th entry to en.json `wizSteps`; optionally backfill locale files.

- [ ] **UV-H2. ~16 STR keys not in en.json — permanently untranslatable.**
  `lifetimeSaved`, `lifetimeSavedHint`, `binPerItemRestoreHint`, `clearAll`, `clearAllConfirm`, `clearAllNothing`, `langFilterLabel`, `langFilterAll`, `ctxIgnoreFolder`, `ctxIgnoreType`, `ctxIgnoreExt`, `ctxIgnoreMedia`, `ctxConfirm`, `ctxNothing`, `page`, `restoreOverwritePrompt`. Covers context menu, pagination, bulk-clear, per-item restore hint, filter labels.
  **Fix:** add all 16 to en.json under top-level `STR`-mapped keys so the merge pipeline exposes them for translation.

- [!] **UV-H3. 5 issue types show English in non-English locale files.**
  `HeavyTranscode`, `FailedTranscode`, `OrphanedDebris`, `LargeTrickplay`, `EmbeddedCoverArt` backfilled by prior UX-C4 fix as **English fallbacks** in locale files (per audit doc audit recommendation). Auditor calling this out as still-English. Explicit trade-off — translators can fill these in as follow-up.

- [x] **UV-H4. "Restoring…" hardcoded in 2 places.**
  `configPage.html:3776` (History restore) and `:6176` (Recycle bin restore). Final state uses `STR.restored`/`STR.restoreFailed`; in-progress state is English-only.
  **Fix:** add `STR.restoring` + en.json entry; use in both handlers.

- [ ] **UV-H5. `window.prompt()` for rename + mkdir.**
  `configPage.html:7574` (rename) and `:8063` (mkdir). Browser-native prompt breaks design consistency, can't show validation errors, blocked in some iframe contexts.
  **Fix:** replace with inline input (rename) or small modal (mkdir). **Deferring to 1.0.1** — larger change, current behavior is functional.

- [x] **UV-H6. `LargeTrickplay` strings differ between JS STR default and en.json.**
  JS STR: title=`"Trickplay space savings"`, hint mentions "scrub-bar preview thumbnails". en.json (added in UX-C4 backfill): title=`"Large trickplay images"`, hint mentions "trickplay sprite thumbnails".
  **Fix:** pick one as canonical; my prior en.json wording is closer to the code semantics; update JS defaults to match.
